# Экспериментальная печать отдельных стикеров — вариант 2

Доступна с 0.4.0 через `LabelPrinter`. Обычные `Printer`, `SyncPrinter` и CLI
сохраняют прежние способы печати. Два алгоритма не используются в одной сессии.
Master Manager использует LabelPrinter для одиночного ID, одного шаблона и серий
шаблонов в режиме этикеток. Одиночные задания и серии сохраняют одно соединение.

TiMini остаётся внешней зависимостью на той же закреплённой ревизии. Его исходники
не копируются в пакет. Используются его BLE-транспорт, декодер/CRC, упаковка
растра и трактовка ошибок. Наш модуль задаёт проверенную последовательность
команд, без штатной дополнительной протяжки непрерывной бумаги. Поддержка
ограничена профилем `v5g_small_203`; это не заявление о поддержке всех устройств V5G.

## Запуск из PowerShell

В активированном виртуальном окружении, из папки CyberpunkIdPrinter:

```powershell
python -m pip install -e ".[printer]"
python .\examples\labels_v2.py --timini-path "..\TiMini-Print"
```

Если `CYBERWALL_TIMINI_PATH` уже задан, аргумент `--timini-path` не нужен.
Адрес по умолчанию — проверенный термопринтер; другой можно указать через
`--address`. Не запускайте одновременно FunPrint, TiMini GUI или Master Manager.

1. Выберите **1**: из состояния `UNKNOWN` выполнится F0, затем сразу печать
   креста и подача 15 мм. Подтверждение после первоначальной калибровки не нужно.
2. Снимите выданную наклейку, оставив подложку в принтере, и закройте крышку.
3. Выберите **3** для подтверждения снятия. Бумага останется выдвинутой.
4. Выберите **1**: выполняются втягивание 25 мм, F0, печать и подача.
   Если подтверждение пропущено, печать запросит его до втягивания:
   выберите **3**, затем снова **1**.

Крест повторяет геометрию успешного эксперимента: 320×240 точек, X_OFFSET=0,
линия два пикселя, в растре шириной 384 точки. Пункт **2** печатает наш ID без имени;
сначала проверьте позиционирование на крестах. Для ID пример устанавливает
`offset_x_mm=-4`, чтобы получить такое же выравнивание влево. Сам класс сохраняет
стандартное центрирование `MediaConfig`; положение ленты задаётся явно в приложении.

Пункт **4** — принудительное восстановление положения, только F0 вперёд.
Пункт **5** — переподключение с повторными попытками; само подключение бумагу
не двигает. В фоне пример опрашивает состояние. После обнаруженного обрыва соединения он
переподключается (по две попытки, пауза 5 с между циклами), не двигая бумагу и
не повторяя задание. Ошибка бумаги не вызывает переподключения и не закрывает меню.
Журнал `thermoprinter-labels-v2-*.log` содержит состояния, RX/TX и traceback.

## Настройки

```powershell
python .\examples\labels_v2.py --timini-path "..\TiMini-Print" --confirmation always --feed-mm 15 --retract-mm 25 --attempts 2 --timeout 20
```

- `--confirmation always` (по умолчанию): подтверждение перед каждым следующим
  реверсом при печати из `PRESENTED`. После калибровки или восстановления\n  подтверждение не нужно. Удалённый режим `recovery` больше не поддерживается.
- `--confirmation never`: не спрашивать; оператор/приложение обеспечивает снятие
  наклейки до следующего задания. Принтер не подтверждает снятие датчиком.
- `--feed-mm 15`, `--retract-mm 25`: диапазон 0.25–25 мм, округление до 0.25 мм.
  Шкала основана на эксперименте, не на DPI. Фактическое обратное перемещение
  и насыщение команды требуют проверки на конкретном устройстве/ленте.
- `--attempts 2`: всего две попытки подключения, пауза 1 с между ними.
- `--timeout 20`: передаётся BLE-клиенту и ожиданиям операций; не общий предел
  длительности connect(), который также включает поиск и подготовку GATT.
- `--scan-timeout 15`: отдельное время поиска перед каждой попыткой.
- `--position-timeout 20`: ожидание ответа F0, без автоматического повторения.
- `--settle 3`: пауза после растра, минимум 2 с. Это НЕ сигнал
  физического завершения печати. Во время ожидания уведомления обрабатываются.

С версии 0.4.1 растр отправляется одним вызовом штатного поточного механизма
TiMini: размер BLE-порций и задержки определяет профиль. Дополнительного дробления
по 20 байт и пауз на стороне нашего кода нет; байты команд печати не изменены.

`--motion-settle 5` — отдельная пауза после подачи/втягивания (минимум 2 с).
Она не подтверждает физическое завершение движения. Для проверки пропуска
стикера попробуйте `--motion-settle 10`, сохранив расстояния 15/25 мм.
Если при полностью остановившемся реверсе F0 всё равно пропускает наклейку,
увеличение задержки не решает причину: нужны наблюдения положения после реверса.
В журнал записываются возврат отправки движения, конец ожидания и начало F0.
AE 00 трактуется как возобновление потока, а не доказанный сигнал остановки мотора.

## API и восстановление

```python
from cyberwall_id_printer import LabelPrinter, LabelSettings, RemovalRequired

printer = LabelPrinter(timini_path="../TiMini-Print", settings=LabelSettings())
await printer.connect("EB:11:06:26:77:26")
try:
    await printer.print_id("123456789", "РОЗА ФОН ПРАУНХАЙМ")
except RemovalRequired:
    # Отобразить запрос в UI. Задание библиотекой НЕ сохранено.
    pass
# Когда оператор действительно снял наклейки:
# await printer.confirm_removed()
# await printer.print_id("123456789", "РОЗА ФОН ПРАУНХАЙМ")
await printer.disconnect()
```

Все методы используются на одном asyncio loop. Операции сериализованы.
`poll()` обновляет статус без движения; вызывайте периодически, если приложение
ждёт ввод. `on_event(dict)` выполняется на loop приложения. Состояния:
`disconnected`, `unknown`, `ready`, `presented`. `recover()` только позиционирует
вперёд. `confirm_removed()` не двигает бумагу и допустим только в `PRESENTED`.\nПосле успешного `recover()` состояние — `READY`.

После подключения, тайм-аута, отмены или сообщения о проблеме положение неизвестно.
Даже короткая ошибка с последующим нормальным статусом сбрасывает позицию и
подтверждение снятия. Норма не является доказательством закрытой крышки. Первая
печать после потери позиции начинается с F0 без реверса и сразу продолжается\nпечатью, без запроса снятия наклейки после калибровки.

Во время печати ошибка прекращает дальнейшую отправку; `LabelOperationError`
содержит `stage`, `may_have_printed` и исходную причину (`__cause__`). Операция
не повторяется и не продолжается после переподключения. Отключение BLE не является
командой остановки двигателя: уже принятые принтером данные могут выполняться.

Базовые статусы V5G: 01/09 — нет бумаги (также наблюдалось при открытой крышке),
04 — перегрев, 08 — низкое напряжение. Неизвестные статусы блокируют движение.
Снятие стикера и физическое завершение растра достоверно не определяются;
`physical_completion_confirmed` остаётся false.

Код проверяется автоматическими тестами, включая реальные кодеки TiMini без
Bluetooth. Перенесённый вариант ещё требует проверки на физическом принтере.

## Ручное перемещение бумаги

В подключённой сессии доступны оба направления:

```python
await printer.move_paper(10)  # Подать вперёд на 10 мм.

# Приложение предварительно получает подтверждение фактического снятия этикеток:
await printer.move_paper(10, reverse=True, removed=True)  # Втянуть на 10 мм.
```

Расстояние — конечное число от 0.25 до 25 мм. Ожидание после перемещения
берётся из `LabelSettings.motion_settle_seconds`. Метод не печатает и
не калибрует ленту. Из `UNKNOWN`, `READY` и `PRESENTED` ручное движение
переводит положение в `UNKNOWN`, в том числе при ошибке или отмене операции.
Для возврата в `READY` вызовите `recover()`; либо следующая печать сама
выполнит калибровку вперёд. Без соединения движение недоступно.

Для ручного втягивания `removed=True` обязателен даже при
`confirmation="never"`. Без него возникает `RemovalRequired` до движения.
Предыдущий вызов `confirm_removed()` этот аргумент не заменяет.
Неверное расстояние вызывает `ValueError` без изменения положения.
Ошибки статуса и транспорта передаются вызывающему приложению; ручное движение
не оборачивает их в `LabelOperationError` и не повторяется автоматически.

В Master Manager команды находятся в обоих меню печати:
`3` — калибровка, `4 10` — вперёд на 10 мм, `5 10` — назад на 10 мм
с подтверждением снятия. Длины и ожидания одиночной печати задаются в
`[printer.labels]` файла `config.toml` Manager.
В `examples/labels_v2.py` отдельных пунктов ручной подачи пока нет:
его пункт 4 по-прежнему означает восстановление, а пункт 5 — переподключение.



### Состояние устройства и отсутствие бумаги

`LabelPrinter.device_status` хранит текущую причину, отдельно от положения
`LabelPrinter.state`: `unknown` (нет свежего статуса), `normal` (нормальный ответ)
или код неисправности TiMini, например `paper_out`. Все события `on_event`
содержат `device_status`; событие `device_status` также содержит сырой `status`.

`await printer.poll()` обновляет состояние без движения бумаги. При неисправности
выбрасывается публичный `DeviceStatusError` с полями `reason` и `status`.
Свежий нормальный ответ снимает `paper_out`, но оставляет положение `UNKNOWN`.
После замены рулона и закрытия крышки вызови `await printer.recover()`:
только успешная калибровка переводит положение в `READY`. Сам опрос не печатает
и не калибрует. Явно запрошенная печать из `UNKNOWN`, как и раньше, сначала
выполняет калибровку, затем печатает.

При отключении/потере связи актуальный статус становится `unknown`; после
подключения нужен новый опрос. Нажатие Enter и подтверждение снятия этикетки
не снимают неисправность без ответа устройства.

Ошибка печати `LabelOperationError` сохраняет `reason`, `status`, `stage` и
`may_have_printed`; `LabelPrinter.last_error` хранит последнюю ошибку печати
даже после нормального опроса. При отказе на этапах `printing`/`advancing`/`presenting`
наклейка могла напечататься: перед повтором проверь результат. Автоматического
повтора нет. Ожидаемые ошибки устройства не выводят traceback на обычном уровне
логирования; подробности доступны на уровне DEBUG.

В Master Manager опрос работает в фоне, пока активен `LabelPrinter`. При
отсутствии бумаги исправное BLE-соединение сохраняется, причина показывается
по-русски, а меню печати остаётся открытым. Это относится и к сериям этикеток:
после ошибки оставшиеся копии не отправляются и не сохраняются для повтора.

## Несколько копий на этикетках (1.3.0)

```python
printer = LabelPrinter(settings=LabelSettings(gap_mm=2.0, feed_mm=15.0))
await printer.connect("EB:11:06:26:77:26")
result = await printer.print_copies(image, copies=3)
# Или нарисовать ID один раз и напечатать три копии:
# result = await printer.print_id("123456789", "РОЗА", copies=3)
```

`print_copies(image, copies)` принимает 1–100 копий одного монохромного изображения.
Требования к изображению такие же, как у `print_image`: ширина 384 точки,
высота не больше настроенной этикетки. Для полной этикетки используй растр
полной высоты, например 240 строк при 30 мм и 203.2 DPI: короткий растр
сам по себе не дополняется до полной высоты. Изображение копируется до начала
движения. `print_image(image)` сохраняет прежний алгоритм одного экземпляра.

Подготовка первой копии общая с одиночной печатью:

- UNKNOWN: калибровка вперёд, затем сразу печать.
- PRESENTED: обычное подтверждение снятия, втягивание `retract_mm`, калибровка.
- READY: сразу печать.

Каждая копия печатается с ожиданием `settle_seconds`. Между копиями выполняется
подача на `gap_mm` и ожидание `motion_settle_seconds`, затем проверяется статус.
Промежуточного втягивания, калибровки и подтверждения снятия нет. После последней
копии вместо зазора выполняется подача `feed_mm` с обычным ожиданием и проверкой
статуса, после чего устанавливается PRESENTED. Следующее задание потребует
снятия всех выданных наклеек перед обратным втягиванием при `confirmation=always`.

`LabelSettings.gap_mm` — расстояние между этикетками, по умолчанию 2 мм,
диапазон 0.25–25 мм. Backend округляет движение до 0.25 мм. В Master Manager
параметр задаётся как `gap_mm = 2.0` в `[printer.labels]` файла `config.toml`.
Старые конфиги без этого параметра получают значение 2 мм.

Серия удерживает блокировку до выдачи последней копии. При ошибке, отмене или
смене служебного epoch дальнейшая печать прекращается, положение становится
UNKNOWN. Ошибка на этапе подачи между копиями имеет `stage="advancing"` и
`may_have_printed=True`. Задание и его остаток не повторяются автоматически.
`PrintResult.copies` содержит запрошенное количество; физическое завершение
по-прежнему не подтверждается. Расстояния и накопление смещения в серии нужно
проверить на реальном принтере и используемом рулоне.
