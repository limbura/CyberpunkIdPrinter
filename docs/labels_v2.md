# Экспериментальная печать отдельных стикеров — вариант 2

Доступна с 0.4.0 через `LabelPrinter`. Обычные `Printer`, `SyncPrinter` и CLI
сохраняют прежние способы печати. Два алгоритма не используются в одной сессии.
Master Manager пока не переведён на новый режим.

TiMini остаётся внешней зависимостью на той же закреплённой ревизии. Его исходники
не копируются в пакет. Используются его BLE-транспорт, декодер/CRC, упаковка
растра и трактовка ошибок. Наш модуль задаёт проверенную последовательность
команд, без штатной дополнительной протяжки непрерывной бумаги. Поддержка
ограничена профилем `v5g_small_203`; это не заявление о поддержке всех устройств V5G.

## Запуск из PowerShell

В активированном виртуальном окружении, из папки CyberpunkIdPrinter:

```powershell
python -m pip install -e ".[printer]"
python .\examples\labels_v2.py --timini-path "..\TiMini-Print"
```

Если `CYBERWALL_TIMINI_PATH` уже задан, аргумент `--timini-path` не нужен.
Адрес по умолчанию — проверенный термопринтер; другой можно указать через
`--address`. Не запускайте одновременно FunPrint, TiMini GUI или Master Manager.

1. Выберите **1**. Сначала произойдёт F0; при стандартных настройках печать
   остановится с запросом снять всё выступающее после позиционирования.
2. Снимите выступающие наклейки, оставив подложку в принтере, и закройте крышку.
   Выберите **3**, затем снова **1**: напечатается крест и выполнится подача 15 мм.
3. Снимите наклейку и выберите **3**. Бумага останется выдвинутой.
4. Выберите **1**: только теперь выполняются втягивание 25 мм, F0, печать и подача.

Крест повторяет геометрию успешного эксперимента: 320×240 точек, X_OFFSET=0,
линия два пикселя, в растре шириной 384 точки. Пункт **2** печатает наш ID без имени;
сначала проверьте позиционирование на крестах. Для ID пример устанавливает
`offset_x_mm=-4`, чтобы получить такое же выравнивание влево. Сам класс сохраняет
стандартное центрирование `MediaConfig`; положение ленты задаётся явно в приложении.

Пункт **4** — принудительное восстановление положения, только F0 вперёд.
Пункт **5** — переподключение с повторными попытками; само подключение бумагу
не двигает. В фоне пример опрашивает состояние. После обнаруженного обрыва соединения он
переподключается (по две попытки, пауза 5 с между циклами), не двигая бумагу и
не повторяя задание. Ошибка бумаги не вызывает переподключения и не закрывает меню.
Журнал `thermoprinter-labels-v2-*.log` содержит состояния, RX/TX и traceback.

## Настройки

```powershell
python .\examples\labels_v2.py --timini-path "..\TiMini-Print" --confirmation recovery --feed-mm 15 --retract-mm 25 --attempts 2 --timeout 20
```

- `--confirmation always` (по умолчанию): подтверждение перед каждым следующим
  реверсом, а также после восстановления, которое могло выдвинуть лишнюю наклейку.
- `--confirmation recovery`: спрашивать только после восстановления положения.
- `--confirmation never`: не спрашивать; оператор/приложение обеспечивает снятие
  наклейки до следующего задания. Принтер не подтверждает снятие датчиком.
- `--feed-mm 15`, `--retract-mm 25`: диапазон 0.25–25 мм, округление до 0.25 мм.
  Шкала основана на эксперименте, не на DPI. Фактическое обратное перемещение
  и насыщение команды требуют проверки на конкретном устройстве/ленте.
- `--attempts 2`: всего две попытки подключения, пауза 1 с между ними.
- `--timeout 20`: передаётся BLE-клиенту и ожиданиям операций; не общий предел
  длительности connect(), который также включает поиск и подготовку GATT.
- `--scan-timeout 15`: отдельное время поиска перед каждой попыткой.
- `--position-timeout 20`: ожидание ответа F0, без автоматического повторения.
- `--settle 3`: пауза после растра и движения, минимум 2 с. Это НЕ сигнал
  физического завершения печати. Во время ожидания уведомления обрабатываются.

## API и восстановление

```python
from cyberwall_id_printer import LabelPrinter, LabelSettings, RemovalRequired

printer = LabelPrinter(timini_path="../TiMini-Print", settings=LabelSettings())
await printer.connect("EB:11:06:26:77:26")
try:
    await printer.print_id("123456789", "РОЗА ФОН ПРАУНХАЙМ")
except RemovalRequired:
    # Отобразить запрос в UI. Задание библиотекой НЕ сохранено.
    pass
# Когда оператор действительно снял наклейки:
# await printer.confirm_removed()
# await printer.print_id("123456789", "РОЗА ФОН ПРАУНХАЙМ")
await printer.disconnect()
```

Все методы используются на одном asyncio loop. Операции сериализованы.
`poll()` обновляет статус без движения; вызывайте периодически, если приложение
ждёт ввод. `on_event(dict)` выполняется на loop приложения. Состояния:
`disconnected`, `unknown`, `ready`, `presented`. `recover()` только позиционирует
вперёд. `confirm_removed()` не двигает бумагу и недопустим до позиционирования.

После подключения, тайм-аута, отмены или сообщения о проблеме положение неизвестно.
Даже короткая ошибка с последующим нормальным статусом сбрасывает позицию и
подтверждение снятия. Норма не является доказательством закрытой крышки. Первая
печать после потери позиции начинает с F0 без реверса. При режиме подтверждений
после этого нужно снять всё выступающее и подтвердить, затем снова запросить печать.

Во время операции ошибка прекращает дальнейшую отправку; `LabelOperationError`
содержит `stage`, `may_have_printed` и исходную причину (`__cause__`). Операция
не повторяется и не продолжается после переподключения. Отключение BLE не является
командой остановки двигателя: уже принятые принтером данные могут выполняться.

Базовые статусы V5G: 01/09 — нет бумаги (также наблюдалось при открытой крышке),
04 — перегрев, 08 — низкое напряжение. Неизвестные статусы блокируют движение.
Снятие стикера и физическое завершение растра достоверно не определяются;
`physical_completion_confirmed` остаётся false.

Код проверяется автоматическими тестами, включая реальные кодеки TiMini без
Bluetooth. Перенесённый вариант ещё требует проверки на физическом принтере.
